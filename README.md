# Nesto – 2D nesting in the browser

Streamlit app + Neon Postgres. Enter part dimensions (or import DXF drawings), set the sheet size, click **Nest**.

## Run
```bash
pip install -r requirements.txt
cp .streamlit/secrets.toml.example .streamlit/secrets.toml   # add your Neon DATABASE_URL
streamlit run app.py
python -m pytest tests
```

## Features
- **Any shape**: rectangle, circle, ellipse, triangle, right triangle, obround from the table, **STEP files of flat parts** (largest flat face -> outline + holes), or **any closed outline from DXF** (lines, arcs, circles, polylines, splines; inner contours become holes that other parts can fill).
- **Smart search** (irregular parts): builds rigid 2-up/4-up clusters (e.g. right triangles hypotenuse-to-hypotenuse), tries 4 placement rules and randomised restarts for a chosen time budget (Search effort: Quick / Normal 15 s / Thorough 60 s) and keeps the best layout.
- **Regular scrap**: sheet count always comes first. Scrap worth keeping = a free region that is rectangular (its biggest rectangle fills >= 70 % of it), reaches the sheet edge, is at least 15 % of the sheet's narrow side thick and big enough; holes in parts, irregular wedges and thinner strips are waste. Layouts are ranked by scrap quality = area x squareness (short side / long side), best piece first, so a big square beats a long thin strip; ties go to the layout that keeps the biggest strip whole. **Small parts go into the smallest gap**: every free region on every sheet where the part fits without cutting regular scrap is considered, and the smallest one wins (a tight pocket beats the long open strip). Only if no such gap exists does a small part take the spot that costs the least scrap. Scrap pieces are drawn as green dashed boxes.
- **Settle pass + bottom preference**: after the search, every part of the winning layout slides down, then left, as far as it can (exact geometry, never closer than the part spacing, never into the margin; parts lying inside the hole of another part are respected). Parts end up flush on the bottom/left edge and the free space collects at the top/right. A sheet is kept settled only if its scrap is not worse than before. When two layouts are otherwise equal, the lower one (parts nearer the bottom edge) wins.
- **Flipping**: every part has *Can rotate* and *Can flip* ticks (both on by default; both sides of the sheet are assumed to be the same). With *Can flip* on, the engine may also place the mirror image of a part (turned over) - useful for asymmetric parts, free for symmetric ones (a mirror image that is just a rotation is skipped; mirror images are tried at the right-angle rotations and the angles that lay a straight edge flat). Flipped layouts cost more computing time, so they are explored after the usual layouts (in *Quick* mode one flip layout is always included) and the best layout wins. Switch *Can flip* off for parts with a finish side, grain direction, handing or a bend direction that matters. Pairs built from a part flip consistently.
- **True-shape nesting** (raster/FFT based): rotations in 90/45/30/15 degree steps, edge margin, part spacing, multi-sheet. Pure-rectangle jobs use an exact, instant MaxRects engine.
- **DXF export** of the nested sheets: ZIP with one DXF per sheet, or all sheets side by side in one DXF. Layers: `SHEET` (sheet outline), `CUT` (closed part outlines and holes), `LABELS` (part names, optional). Units: same as the sheet size you typed (mm).
- **Parts details** tab: every part of the project (nested or not - quantity 0 keeps a part in the project without nesting it) with a search box; click a name to see its dimensioned drawing (overall size, edge lengths, diameters, hole sizes) plus area and cut length.
- **Cut list (Excel)**: *Export → Cut list (Excel)* downloads an .xlsx with four tabs: *Summary* (settings, sheets, parts, utilization with two decimals, time, one line per sheet), *Parts* (requested vs placed quantity - mismatches are marked red -, size, area, which sheets each part is on), *Placements* (one line per placed part: sheet, x/y of its box, box length/width, rotation, flipped, area) and *Offcuts* (the usable scrap pieces of each sheet). Values are plain numbers (no formulas), so previews on phones show them too.
- **Rotation step down to 1°**: the step menu offers 90°, 45°, 30°, 15°, 10°, 5°, 2° and 1°. Steps finer than 15° search with the 15° set (plus the angles that lay an edge flat) and then fine-tune the best layout with all angles within ±7.5° of the angles it uses; the fine layout only replaces the coarse one when it is better. This keeps 1° to roughly 1.5–2× the time of 15° instead of 15×.
- **Parts table**: folded into a one-line "Expand parts" box (click to open) and numbered 1, 2, 3 ... in a first "No." column.
- **Hold area**: in edit mode every sheet has a hold box below it. Drag a part out of the sheet into the box to set it aside while you rearrange the others (rotate / flip work there too), then drag it back in; it only goes back where there is room. Parts in the hold area are not on the sheet: they are left out of the drawings, the exports and the counts, and a banner (plus a message when you switch editing off) names the parts you left outside.
- **Nesting survives a locked phone**: irregular-part nesting runs in a background thread of the server (`nest_job.py`) and saves its run to the History itself. The page shows progress with a Cancel button; if the browser connection is lost (phone locked, tab put to sleep) the nesting keeps running, and when you open the page again the finished result is shown (or the progress, if it is still running). Rectangle-only jobs are instant and run directly.
- **Scrap includes the edge margin**: a scrap piece that reaches the edge margin is shown (and exported in the cut list) as running on to the sheet edge, because the margin strip is scrap too. Next to a part nothing is added.
- **STEP export**: besides DXF, the sheets can be downloaded as STEP - one file per sheet (ZIP) or all sheets stacked in one file (a single sheet gives one file). Every part is a named entity: a flat 2D face (outer outline + holes), or a solid plate when you type a thickness in "STEP thickness". The sheet is a 0.5 mm thick solid plate of the sheet size lying under the parts: its upper face is the plane z = 0, which is also where the parts start (the part bottoms touch the sheet top; the plate spans z = -0.5 to 0). The sheet and the parts are coloured: the sheet is light grey, each part has one of ten green / blue colours (deep blue, emerald, sky blue, forest green, cyan, lime, navy, mint, teal, steel blue), parts that touch never share a colour and no part has the sheet's colour. Built when you click download (`step_export.py`, needs `cadquery-ocp`).
- **Cut length**: the run numbers row ends with the total cut length (the border of every part: outlines plus holes; where two parts touch the shared edge counts once for each part), and every sheet title shows its own cut length.
- **Export menu**: one **DXF** button and one **STEP** button, each opening its two choices (files in a ZIP / all sheets in one stacked file); the STEP button also holds the STEP thickness box. Cut list (Excel) and Layout (JSON) stay single buttons.
- **Cut length by part**: under every sheet a folded table lists each part with its outline length, number of holes, hole outline length and cut length, and the sheet total, so the cut length of a sheet can be checked part by part.
- **Part names**: in the sheet drawings a name is written inside its part, as large as fits (down to 5 pt; thin tall parts get it turned by 90°). A part too small for that gets its name outside the sheet, on the sheet edge nearest to it, with a thin leader line and a dot on the part - so the names are spread around the sheet, not collected on one side. In the edit view every name stays inside its part (shrunk and turned to fit), because the parts move.
- **File names**: every downloaded file (DXF, STEP, ZIPs, the files inside the ZIPs, cut list, JSON) starts with the project name and the run number, e.g. `Job_1042_run28_sheets_dxf.zip`, `Job_1042_run28_sheet_01.dxf`, `Job_1042_run28_cutlist.xlsx`.
- **Same part, same colour**: a part has the same colour on every sheet of a run (in the sheet drawings and in the edit view), so a part can be recognised across sheets at a glance; colours follow the order in which the part names first appear over the whole run.
- **Re-pack pass**: after the search, every sheet that carries two or more irregular parts gets a second look: those parts are placed again in every order and also as a rigid pair of two different parts whose edges mate (`_best_pair_mixed`), and a new arrangement replaces the old one only when the sheet is better (offcuts first, then compact free space; the number of sheets never changes). The time it may take grows with the search effort (about 10 s in Quick, 22 s in Normal, 58 s in Thorough). Offcuts also count the usable rectangles inside an L- or U-shaped free region now, so such sheets are no longer shown as having no scrap.
- **Machining (G-code)** (currently switched off: `SHOW_MACHINING = False` in `app.py`; the code is kept): a fourth tab with a tool library (T number 1-26, diameter, flutes, rpm, feed, plunge, step-down, coolant; one library for all projects) and per-project machining settings (material thickness, overcut, rapid / feed-in heights, spiral ramp or straight plunge, climb or conventional, tabs, tool for holes and for outlines, smoothing, file extension). From the nested sheets it makes basic 2.5D contour toolpaths: outlines cut on the waste side and holes from inside, offset by the tool radius in software (no G41/G42), holes of all parts first, then the outlines, nearest-neighbour order. The G-code follows the Mariani CR Onsrud 336G18CW7 FANUC post (`post/*.gpp`, `post/*.vmid`): `%` and `<name>`, `G90 G21 G40 G49 G80 G94 G98 G17`, G56, `M6 T..`, `G0 C0.`, `S.. M3`, `G05.1 Q1 R7` smoothing, `G43 H..`, coolant M8 / M14 / M9, `M5`, `M30`. It warns when the tool is bigger than the gap between parts (set the nest part spacing to at least the tool diameter) or than a hole. Preview of the toolpaths and download per sheet or as a ZIP (file names with project and run number).
- **Main tabs**, in workflow order: 1 · Import files, 2 · Parts details, 3 · Nesting, 4 · NestoCAM.
- **NestoCAM tab** (the CAM process): the CAM process as a list of steps (the old Machining tab stays switched off). Step 1 - Geometry: the bottom outline of every part (outline + each hole, at Z = 0 = the bottom of the material; work coordinate system at the lower left corner of the sheet, X along the length, Y along the width, Z up, top of the material = thickness), with an isometric picture of the WHOLE sheet seen from the origin corner, drawn to scale (the stock slab in light grey, every part transparent with dotted edges and its height, its bottom contour (the geometry, the future toolpath) in red, the length, width and thickness as plain numbers outside the sheet, a small thin X Y Z system at the origin, always at true scale), the number of outlines, a plan view and a table of the chains. The material thickness is saved with the project. NestoCAM has sub-tabs, one per step: 1 · Geometry and 2 · Tools. The **Tools** tab is the tool library (shared by all projects): a list first; the list shows only No., Name, Type, Diameter and Flutes; clicking another tool switches the details beside it (read-only until **Edit** is pressed; **Save tool** saves and locks them again, **Cancel** drops the changes) (a form to change it, also renumber, or delete it, with a guide picture), **New tool** adds one, and **Use for CAM** (the button above the list, for the ticked tool) chooses the tool for the next CAM steps of the project (saved with the project), and a guide picture that explains the dimensions: catalog number, name, type (END MILL), flutes, D, SD, AD, SA, CL, SL, TL, CH, OHL, helical angle. The tools saved by the old Machining tab were deleted once (the new library is its own table, `nesto_tools`).
- **Sidebar order**: menu (New / Load / Save / Rename / Delete), then the run history, then the sheet and nesting settings.
- **Move parts by hand**: switch on *Edit parts* above the sheets. Click a part (or touch it): a small menu (it closes when you click elsewhere on the page or press Esc) offers **Move** (drag it), **Rotate** (90° or 15° either way, or any angle you type in the Angle box; ⟲ = counter-clockwise, ⟳ = clockwise; it turns about the part's centre of mass, so turning back returns to the same spot) and **Flip** (left–right or top–bottom). Rotate and Flip turn the part in place about its centre, and only when it has room (inside the edge margin and at the part spacing from its neighbours; a part at the sheet edge is pushed back inside the margin). Editing re-runs only the sheet area (not the whole page), several quick edits in a row are queued and never lost, and the export files are built when you click, from the layout as it is then. Dragging: it moves freely in the empty space around it and **stops at its limit**: the edge margin, the part spacing to its neighbours (outline to outline, so it can slide into narrow gaps), and other parts; it never turns red or jumps back, sliding along the obstacle when you keep pushing. Arrow keys nudge the selected part (1 unit, Shift 10, Ctrl 0.1). *Undo last move*, *Reset layout* and *Save changes* (overwrites the layout of that run) and *Save as new run* (keeps the original run and stores the moved layout as a new one). Exports and the cut list always use the moved layout. Every move is checked again on the server with exact geometry (`layout_edit.py`), so the layout can never contain overlapping parts. The editor is a small custom component (`components/sheet_editor`, plain JavaScript, no build step); its collision code is tested against Shapely.
- **Unsaved-moves protection**: a warning shows how many hand moves are not saved yet. The browser asks before you reload or close the page, and a dialog (Save & continue / Discard & continue / Cancel) appears before *Load run* or *Nest* would replace them; switching project needs a tick to discard them.
- **History**: the sidebar lists the open project's past runs (number, sheets, utilization, time). *Load run* shows one again; *Delete…* removes one or several runs (pick them in a list or *Select all*; it only ever deletes runs of the open project).
- **Header**: the puzzle-piece logo 🧩 next to the big "Nesto" title, with the open project's name below it in a smaller, lighter font (the same logo is the browser-tab icon).
- **Project menu** (left sidebar): New / Load / Save / Rename / Delete. Rename keeps the parts, settings and history; duplicate names (any letter case) are refused. Sheet and nesting settings are saved with the project automatically the moment you change them; Save also writes the parts (settings first, each step reported separately). Load restores both. The open project is kept in the page address, so a browser reload reopens it.
- Neon tables: `projects`, `parts`, `nest_runs` (created/migrated automatically).

## Notes
- Irregular nesting resolution is set by *Precision* (cell = longest sheet side / 500, 800 or 1400). Parts end up about 1-2 cells further apart than the spacing you ask for; use *Fine* for tighter results. Overlap-free placement is guaranteed (checked by tests).
- Circles/ellipses are polygons slightly larger than the true curve (0.05 %), so real parts never overlap.
